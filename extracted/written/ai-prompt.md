# Context-Specific AI Prompt

You are assisting with a small, public static portfolio website for a University of Michigan–Flint graduate student and working financial analyst.

## Project purpose
Customize the instructor-approved HTML/CSS/JavaScript portfolio template into an online professional portfolio suitable for internship, recruiting, and technical-review audiences.

## Existing system
- Existing system: an HTML/CSS/JavaScript portfolio template.
- The starter repository's overall structure and required attribution/license must be preserved.

## Source of truth
Use the attached/provided professional resume and `content-notes.md` as the source of truth. Do not invent facts.

## Allowed changes
- Portfolio text/content
- Existing HTML sections and navigation
- Existing CSS needed for presentation/responsiveness/accessibility
- Small JavaScript/front-end corrections only where necessary

## Do not add
- Backend
- Database
- Login/authentication
- Analytics tracker
- External data collection
- API keys, secrets, or tokens
- Invented professional history, credentials, projects, links, or skills

## Acceptance criteria
1. The landing page displays Christian Benjamin Namath Heiney and a concise professional role related to Asset Liability Management and financial analytics.
2. The portfolio contains at least two substantive sections describing professional experience and education, using only verified resume information.
3. Navigation links move to the intended portfolio sections without broken links.
4. The page remains readable and usable on a narrow mobile viewport without horizontal scrolling or overlapping content.
5. No private contact information or placeholder/template identity remains in the published site.
6. External/project links, if included, use real destinations only; no invented URLs are presented as factual links.
7. Keyboard navigation is usable and images have meaningful alternative text or are explicitly decorative.
8. The browser console contains no unexplained errors during normal page use.

## Technical/accessibility constraints
- Preserve required license and attribution.
- Keep the site static.
- Maintain readable contrast.
- Preserve or improve keyboard navigation.
- Use meaningful link text.
- Give informative images useful alt text; use empty alt text for genuinely decorative images.
- Do not expose private information.
- Avoid unnecessary rewrites of unrelated starter files.

## First provide — do not modify files yet
1. A file-by-file implementation plan.
2. Assumptions and risks.
3. A proposed test checklist mapped to the acceptance criteria.
4. Questions that must be answered before implementation.

After the plan is reviewed, implement incrementally in small, understandable changes.
